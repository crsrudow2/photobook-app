# Plan: Build storefront UI for photo book app

## Assumptions
- Next.js 16.2.3 App Router with Tailwind CSS v4 already installed
- `params` and `searchParams` are Promises (Next.js 16 breaking change) — must be awaited
- `PageProps` / `LayoutProps` are globally available (no import needed), generated at build time
- Tailwind v4: custom colors defined in `@theme` block in globals.css (no tailwind.config.js)
- No database yet — all product data will be hardcoded mock data
- Purple accent: `#512dcb`
- Server components by default; `'use client'` only for interactive elements

## Acceptance Criteria
1. `src/app/(shop)/page.tsx` exists and renders hero section, product category grid, and featured products
2. `src/app/(shop)/products/page.tsx` exists with filter sidebar (size, cover type, price) and product grid
3. `src/app/(shop)/products/[slug]/page.tsx` exists with product images, size/cover selector, price, Add to Cart button, breadcrumbs, reviews section
4. `src/components/ui/Button.tsx`, `Card.tsx`, `Badge.tsx`, `Select.tsx` all exist with Tailwind-only styling
5. `src/components/layout/Header.tsx` and `Footer.tsx` exist with nav, cart icon, and user menu
6. `src/app/(shop)/layout.tsx` wraps pages with Header + Footer
7. `next build` exits with code 0 (or `tsc --noEmit` exits 0 and eslint passes)
8. Purple accent `#512dcb` used consistently across brand elements

## Decision Log
- Using hardcoded mock data: no DB schema implemented yet, task is UI-only
- Filters in products page use `useSearchParams` client hook in a client wrapper component; page itself stays server component reading searchParams prop
- Select component built from scratch (no Radix) to meet "Tailwind only, no external UI lib" requirement
- Header user menu uses CSS `group` + `hover` for dropdown (no state needed), falls back to client component if needed
- Prisma 7 removed `url` from schema datasource — moved to `prisma.config.ts` with `defineConfig`
- Prisma 7 requires a driver adapter for PrismaClient — installed `@prisma/adapter-pg` and `pg`
- Used next-auth v4 (resolved by npm) — v4 App Router pattern: export GET/POST from NextAuth handler

## Surprises & Discoveries
- Next.js 16 renames `middleware.ts` to `proxy.ts` (not relevant to this task but noted)
- `context.params` is now a Promise in Next.js 15+ route handlers
- Prisma 7 is a major breaking change: no url in schema, requires adapter or accelerateUrl in PrismaClient constructor, config moved to `prisma.config.ts`
