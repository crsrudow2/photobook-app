## Decision Log
- Prisma 7 removed `url` from schema datasource — moved to `prisma.config.ts` with `defineConfig`
- Prisma 7 requires a driver adapter for PrismaClient — installed `@prisma/adapter-pg` and `pg`
- Used next-auth v4 (resolved by npm) — v4 App Router pattern: export GET/POST from NextAuth handler
- `@auth/prisma-adapter` v2 requires casting as `NextAuthOptions['adapter']` due to type mismatch with next-auth v4
- Used JWT session strategy (not DB sessions) to avoid adapter session table conflicts with credentials provider
- Added `tsx` devDependency for running `prisma/seed.ts`
- Added db:generate, db:migrate, db:seed, db:studio npm scripts

## Surprises & Discoveries
- Next.js 16 renames `middleware.ts` to `proxy.ts` (not relevant to this task but noted)
- `context.params` is now a Promise in Next.js 15+ route handlers
- Prisma 7 is a major breaking change: no url in schema, requires adapter or accelerateUrl in PrismaClient constructor, config moved to `prisma.config.ts`
- `env()` from `@prisma/config` throws if env var is not set — using `process.env.DATABASE_URL` instead in prisma.config.ts
- Prisma CLI does not auto-load `.env` for `prisma.config.ts` evaluation — must pass DATABASE_URL as shell env or use `dotenv`
