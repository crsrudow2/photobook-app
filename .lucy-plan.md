# Plan: Set up full project foundation for photobook app

## Assumptions
- Next.js 16.2.3 is installed (breaking changes vs 14 — middleware renamed to proxy, params are Promises)
- No prisma, next-auth, or other deps installed yet
- Docker Compose will provide PostgreSQL locally
- next-auth v5 (Auth.js) should be used as it's compatible with Next.js App Router
- Credentials provider with bcrypt password hashing

## Acceptance Criteria
1. `docker-compose.yml` exists at repo root with a `postgres` service on port 5432, db/user/password all `photobook`
2. `prisma/schema.prisma` defines User, Product, Template, Project, CartItem, Order, OrderItem models with all fields from spec
3. `npm install` succeeds after adding: prisma @prisma/client next-auth @auth/prisma-adapter bcryptjs @types/bcryptjs zod
4. `src/lib/prisma.ts` exports a singleton PrismaClient instance (global singleton pattern for dev hot-reload)
5. `src/lib/auth.ts` exports NextAuth config with credentials provider that validates email/password via bcrypt
6. `src/app/api/auth/[...nextauth]/route.ts` exports GET and POST handlers from NextAuth
7. `prisma/seed.ts` creates 3 photo book Product records with realistic data (name, description, basePrice, slug, etc.)
8. `.env.example` contains DATABASE_URL, NEXTAUTH_SECRET, NEXTAUTH_URL with placeholder values
9. `npx prisma generate` completes successfully (Prisma client generated)
10. `npm run lint` and `npx tsc --noEmit` exit with 0 errors on the new files

## Decision Log
- Prisma 7 removed `url` from schema datasource — moved to `prisma.config.ts` with `defineConfig`
- Prisma 7 requires a driver adapter for PrismaClient — installed `@prisma/adapter-pg` and `pg`
- Used next-auth v4 (resolved by npm) — v4 App Router pattern: export GET/POST from NextAuth handler
- `@auth/prisma-adapter` v2 requires casting as `NextAuthOptions['adapter']` due to type mismatch with next-auth v4
- Used JWT session strategy (not DB sessions) to avoid adapter session table conflicts with credentials provider
- Added `tsx` devDependency for running `prisma/seed.ts`
- Added db:generate, db:migrate, db:seed, db:studio npm scripts

## Surprises & Discoveries
- Next.js 16 renames `middleware.ts` to `proxy.ts` (not relevant to this task but noted)
- `context.params` is now a Promise in Next.js 15+ route handlers
- Prisma 7 is a major breaking change: no url in schema, requires adapter or accelerateUrl in PrismaClient constructor, config moved to `prisma.config.ts`
- `env()` from `@prisma/config` throws if env var is not set — using `process.env.DATABASE_URL` instead in prisma.config.ts
- Prisma CLI does not auto-load `.env` for `prisma.config.ts` evaluation — must pass DATABASE_URL as shell env or use `dotenv`
